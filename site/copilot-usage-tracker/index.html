A GitHub Copilot usage tracker in the MacBook notch

Notchmeter shows the month's AI-credit allowance on a Copilot seat GitHub bills by usage, used, left and the reset on the first of the month, with a pace tick and a projection, beside the notch, from the same endpoint Copilot's own editor plugin asks; on a legacy seat the premium-request allowance, and on Copilot Free the chat and completion quotas. The credits used, a cent each at GitHub's published rate, join the Cost card.

What Notchmeter shows for GitHub Copilot

The strip on the right is drawn from a fixed set of readings that has no Copilot seat on it; a seat that does adds a ring of its own in the same row, in Copilot's yellow.

  • AI credits, on a seat GitHub meters in credits: the month's count used and the remainder against the entitlement where a snapshot carries one, with a pace tick, a projection and the reset on the first of the month. A seat marked unlimited says so rather than drawing a bar.
  • Premium requests on a legacy seat, and Chat and Completions where a plan meters them, Copilot Free's included. Request counts stay counts: multiplying them by an overage rate would invent a bill.
  • Cost: the credits used times a cent, on the Cost card as a row whose source reads AI credits, with the day series being what this Mac observed.
  • Organisation billing, opt-in for org admins: the month's organisation credits and spend as hidden-by-default windows, GitHub's own figures, and kept off the Cost card because they are the whole organisation's month rather than this seat's.
  • Sessions: with the Copilot CLI hook, every running session, a dot on the ring while Copilot waits for a permission, and Allow or Deny from the notch.

Questions

Which Copilot plans does it meter?

Copilot Free's chat and completion quotas; a Pro, Pro+, Business or Enterprise seat that GitHub meters in AI credits, which is how GitHub has billed Copilot since 2026-06-01; and a legacy seat's premium-request allowance. An org admin can opt in to the organisation's month as well. A GitHub account with no Copilot subscription is told so, not shown an empty bar.

Why does it show credits rather than requests times a rate?

Because a cent a credit is GitHub's own published rate, and the credit count is GitHub's own running total, so the figure is GitHub's arithmetic and not Notchmeter's. Request counts on a legacy seat stay counts: multiplying them by an overage rate would invent a bill for requests inside the allowance.

Why is the daily spend for Copilot approximate?

GitHub publishes one month-to-date count and not when each credit was spent, so Notchmeter lays every rise on the day it saw it, sets the month's baseline at its first read rather than charging the whole count to one day, and takes a falling count as the reset. Credits spent while the app was not running land on the day it next looks, and credits spent before it first looked are never charged to any day. The row is tagged an estimate for exactly that reason.

Does it send another client's identity to GitHub?

For the quota read, yes: the endpoint is keyed on the Copilot Chat extension's identifiers and answers no other, so the request carries them. The organisation reads carry Notchmeter's own name. It is the one borrowed identity in the app, and it is stated in docs/privacy.md and in the accuracy document rather than left in the code.

Does it need the gh command line tool?

No. It reads the token Copilot's editor plugin keeps in apps.json or hosts.json first, and gh's hosts.yml only after those. Whichever answers is used, read only, never refreshed or written.

Can I answer a Copilot CLI permission from the notch?

Yes, with the Copilot CLI hook. Copilot's PascalCase PermissionRequest documents the same decision shape as Claude Code's, so the panel opens on the request with Allow and Deny, and it fails open: hand it back, let the hold run out, or quit Notchmeter, and Copilot asks in the terminal as it always has. docs/hooks.md has the events and the fail-open rule.
