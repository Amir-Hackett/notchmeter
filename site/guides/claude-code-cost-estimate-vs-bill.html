Why your Claude Code cost estimate doesn't match your bill

The dollar figure in Claude Code's /usage, in its status line and in Notchmeter's Cost card is worked out on your Mac from token counts and a price table. It is an estimate by construction. Here is exactly how Notchmeter's is built, where it comes from, and every place it is known to part company with the bill.

  • Published 24 September 2026
  • Tested on Notchmeter 0.9.0
  • Sources read 2026-09-01

The short answer

On a Pro, Max, Team or Enterprise seat there is no bill for it to match: the figure is what the same work would have cost at Anthropic's API list prices, and Anthropic says as much. On an API key it is a list-price estimate that cannot see contracted rates, cloud regional premiums, other machines, or the real length of a response that was cut off. The authoritative number is the Usage page in the Claude Console, or your cloud provider's invoice.

First: which bill?

Anthropic's own documentation settles the subscription case in one sentence: "Claude Max and Pro subscribers have usage included in their subscription, so the session cost figure isn't relevant for billing purposes." The figure is still useful. It is the API-equivalent value of the work your sessions did, which is how you compare two days, notice an expensive hour, or judge what a plan is worth to you. It just is not money you owe.

How the estimate is built

Claude Code writes one JSONL transcript per session under ~/.claude/projects. Notchmeter reads every one touched in the last 30 days (plus Claude Desktop's Cowork sessions and any folder you add in Settings), and each response contributes five token counts from the API's own usage object. None of them is estimated: the counts are what the API reported, and each model's tokens are priced at that model's rate.

The five buckets, and the multiplier each takes off the model's base input rate
BucketField in the transcriptPrice
Inputinput_tokensbase input rate
Outputoutput_tokens (thinking tokens are inside it)output rate
5-minute cache writeephemeral_5m_input_tokens1.25 × input
1-hour cache writeephemeral_1h_input_tokens2 × input
Cache readcache_read_input_tokens0.1 × input (0.025 × on Fable 5.1 and Mythos 5.1)

Three more rules come straight from Anthropic's pricing page and the Agent SDK's cost documentation. A response whose usage says inference_geo: "us" is multiplied by 1.1 on every bucket, because US-only inference on Claude 4.6 and later is billed at that premium. A web search adds $10 per 1,000 searches, after the multiplier, which never applies to a per-request fee. And a response marked speed: "fast" on Opus 5 or Opus 4.8 is priced at twice the standard rate.

A worked line, so you can check the arithmetic: one Sonnet 5 response with 2,000 input tokens, 800 output, 5,000 written to the 5-minute cache and 30,000 read from it costs $0.004 + $0.008 + $0.0125 + $0.006 = $0.0305. The same response served from US-only inference costs $0.03355.

Why two tools disagree about the same transcripts

Claude Code writes a streamed response as several lines, one per content block, and they share one message id. Anthropic's documentation says to deduplicate by that id, and since 2026-09-24 Notchmeter groups by it alone. Until then it grouped by the message id and Claude Code's request id together, the pair ccusage uses, which counted a Claude Desktop Cowork response two or three times over: Cowork's transcripts write the request id under another name on some lines and leave it off others, so each of those lines stood on its own. Claude Code's own transcripts carry the request id on every line, and their figures did not move. What differs between tools is which line each keeps, and it matters more than it looks: Claude Code builds each line from the usage reported when the response began, so every line but the last carries a placeholder output count, often single digits. Only the final line has the real one.

Notchmeter keeps the line with the largest output count. Measured across the 3,501 transcripts on the development Mac on 2026-09-01, keeping the first line of each response would have counted 17,975,458 output tokens; keeping the last counts 24,339,282, 35% more. A golden test pins it: three lines of one Fable 5.1 response, with output counts of 3, 3 and 1,090, price to $0.1095, not the $0.05515 that keeping the first would give. If another tool shows you a lower figure for the same day, this is the first place to look.

The other common mismatch is scope. Claude Code's /usage Session block covers one session since its last /clear. Notchmeter's Today covers every transcript on the Mac for the calendar day. Both can be right.

The seven known divergences

These are the things a bill can contain that the estimate does not, in the order they are likely to matter. They are listed in the accuracy document for the same reason they are listed here: a number that cannot show its work should not be on screen.

  1. Interrupted responses. A response that never finished (you pressed Escape, the network dropped) has only placeholder lines, so its output is under-counted. Its input and cache counts are right. It cannot be told apart from a genuinely short reply, so nothing is guessed.
  2. Contracted rates, regional cloud premiums and usage-credit rates, unless you tell the app about them (next section).
  3. Price changes. The table is a dated snapshot. A scheduled job fetches Anthropic's pricing page every week and fails when a row no longer matches.
  4. Other machines and claude.ai. Only this Mac's transcripts, Cowork's and the folders you add are read. Chat on claude.ai is never priced.
  5. Currency. Everything is computed in US dollars. Show costs in converts with a rate you type; nothing is fetched, so a converted figure is only as current as that rate.
  6. Cursor's percentage fields, which Cursor's own staff describe as a different internal metric from spend (see the limits guide).
  7. Copilot's day series. GitHub reports a month-to-date count, so a day's credits land on the day this Mac saw them rise.

Two rules that used to be on this list are now modelled and are not divergences: the web-search fee and fast mode, both since 2026-09-02.

If you pay contracted rates

Anthropic's documentation is plain that Claude Code "computes every cost figure it shows developers at list price, so if your organization pays contracted rates, the figures in /usage, the status line, and OpenTelemetry don't match your bill." Two files change that, and Notchmeter reads both. Claude Code's own modelPricing table in ~/.claude/settings.json is honoured, so the card agrees with Claude Code's figure. Notchmeter's ~/Library/Application Support/Notchmeter/pricing-overrides.json takes the same shape and wins on a clash:

{"claude-opus-5": {"input": 4, "output": 20, "cacheRead": 0.4, "cacheWrite": 5, "cacheWrite1h": 8}}

Rates are dollars per million tokens, and a cache rate you leave out is derived from your input rate with the standard multipliers. An override changes the pricing fingerprint the app's cache is keyed on, so every transcript is re-priced on the next scan.

Codex, Cursor, Copilot and Antigravity

  • Codex is priced from its session rollouts at OpenAI's published standard-tier rates, with cached input taken out of input_tokens before it is priced so it is not charged twice. On a ChatGPT plan it is, like Claude's, the value of the work and not a bill.
  • Cursor is not estimated at all. Every dollar on its row is the one Cursor itself put on that event in its own usage export, which is why the row says billing export.
  • GitHub Copilot is GitHub's own running count of AI credits, a cent each at GitHub's published rate, on seats GitHub meters that way.
  • Antigravity has no row. Its endpoints return quota fractions and no price and no token count, so there is nothing to derive a dollar from, and a $0 would be a claim that it cost nothing.

Check a number yourself

Without the app running and without a Keychain prompt, the app's own executable prints the totals and one clause per tool:

/Applications/Notchmeter.app/Contents/MacOS/Notchmeter --probe --no-prompt

To check one transcript by hand, list its priced lines, keep the line with the largest output_tokens for each message id, price the five buckets from the table, multiply by 1.1 where inference_geo is "us", and add up:

jq -c 'select(.message.usage) | [.timestamp, .message.id, .message.model, .message.usage]' \ ~/.claude/projects/<project>/<session>.jsonl

A model the table does not know is never priced at a guess and hidden: it costs $0 and is listed on the card as Unpriced, so a new model shows up as a gap you can see.
