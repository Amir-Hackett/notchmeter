An Antigravity usage tracker in the MacBook notch

Notchmeter shows the session and weekly quota Antigravity's own panel shows for its model groups, Gemini models, and Claude and GPT models, beside the notch, each with a pace tick, a projection and its reset, from the same Code Assist endpoint Antigravity asks, under Antigravity's own client identity. It needs one Google sign-in through Gemini CLI, and it shows no cost, because Antigravity meters quota rather than money.

What Notchmeter shows for Antigravity

Antigravity and Gemini CLI meter against the same Google backend, so they share one ring; this page is the Antigravity side of it, and the Gemini CLI page the other.

  • The groups Antigravity's panel shows: Gemini models and Claude and GPT models, each with a session, weekly or daily bucket whose length Google declares, so every one has a pace tick and a projection from the first read.
  • The per-model buckets as the fallback when the summary is not answered, grouped by pool, with a length inferred from their resets and said to be.
  • Unknown is not untouched: a bucket with no fraction draws no figure, never 100% left; an explicit 0 is exhausted; and an answer from the host that is not metering you, every bucket untouched at one identical reset, is shown with no figure and a caption rather than as an untouched quota.
  • No cost: Google meters quota, and publishes no price and no token count, so the Cost card has no Antigravity row, not a $0.
  • Sessions: with the Gemini CLI hook installed, the ring also counts Gemini CLI's running sessions and shows a tick when a turn ends; Notchmeter installs nothing into Antigravity's own IDE hooks.

The login is ~/.gemini/oauth_creds.json, the Google login Gemini CLI caches. The Antigravity app and its agy command keep theirs in the Keychain and publish quota only through a local server inside the running app, which Notchmeter does not attach to, so the Antigravity meter needs one Google sign-in through Gemini CLI (gemini, then Login with Google). The token is read, never refreshed or written, and sent only to Google as Authorization: Bearer.

Why there is no cost: the endpoint returns per-group and per-model windows and the fraction of each that is used, no price, and no token count that a published rate could be applied to. Gemini's API rates would not help, because an Antigravity seat is not billed at them. There is nothing to derive a dollar figure from, so none is shown. Every rule on this page is pinned by tests and written down in Antigravity: quota, and no cost.

Questions

Why does the Antigravity meter need Gemini CLI's login?

Because it is the only Google login on disk. The Antigravity app and its agy command keep their token in the Keychain and publish quota only through a local server inside the running app, which Notchmeter does not attach to. The login Gemini CLI caches in ~/.gemini/oauth_creds.json after Login with Google is read, never refreshed or written, and sent only to Google's Code Assist endpoints.

Which windows does it show?

The ones Antigravity's own panel shows: a group for Gemini models and one for Claude and GPT models, each with a session, weekly or daily bucket whose length Google declares, so each has a pace tick and a projection from the first read. When the summary is not answered it falls back to the per-model buckets, grouped by pool, with a length inferred from their resets and labelled as such.

Why is there no cost for Antigravity?

Because Antigravity meters quota, not money. The endpoint returns windows and the fraction of each that is used, with no price and no token count a published rate could be applied to, and an Antigravity seat is not billed at Gemini's API rates. Nothing honest can be derived, so the Cost card has no row for it rather than a $0.

Why does it send Antigravity's identity to Google?

Because the backend picks which product's licence to check from the caller's identity: the same call under a Gemini CLI identity answers an Antigravity-only account with “no valid license”. When the Antigravity markers are on this Mac, the calls carry Antigravity's user agent and client metadata so the right licence is checked. It is another client's identity, sent because the endpoint answers no other, and it is stated in docs/privacy.md rather than hidden.

Why did a meter read untouched, or 100% left, while I was working?

Google meters the quota on one of two deployments, and the other answers every bucket untouched with a reset five hours from the moment it was asked. Notchmeter prefers the host Antigravity's CLI last logged, tries both otherwise, believes the first answer with a live figure, and shows a placeholder answer with no figure and a caption saying so. A window still untouched across three polls while the hook reports your turns loses its figure and says it is unverified.

Does the June 2026 change to Gemini CLI quota affect Antigravity?

That change is to what Google serves the Gemini CLI identity: since June 2026 personal accounts get a refusal there. With the Antigravity markers on this Mac the calls carry Antigravity's identity and the backend checks the Antigravity licence instead. The shutdown sentence is shown only after both hosts have refused, so the wrong host is never mistaken for a lost licence.
