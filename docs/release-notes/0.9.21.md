# Notchmeter 0.9.21

### Cursor

- **A subagent's work is on its conversation's row, not on a row of its own.** Cursor runs a subagent as a chat of its own that no window lists, and what that chat sends names it alone, so until now each subagent stood on the Sessions card as a second session beside the conversation that started it, named after its task and counted as one. Notchmeter now reads from Cursor's database which chat a new conversation works for, before that conversation is given a row, and a subagent's commands and thoughts are activity on its conversation's row, under the subagent line that row already had.
- The conversation's row no longer goes quiet while its subagent works. Everything the subagent did was heard on the other row, so some 45 seconds into a subagent's run the conversation was shown as one that *may be waiting*, with the hand and, where it is on, the notice.
- A subagent finishing is not the turn finishing: its end gives no tick and no *finished* notice, and the conversation's own turn is the only one that does.
- A command a subagent is held for under *Require notch approval* is answered on its conversation's row, and a held command is no longer taken off the notch by a subagent starting beside it.
- The row keeps the conversation's own model while a subagent runs on another. Cursor's two subagent events carry the subagent's model, and the row wore it until the conversation's next event.
- Where Cursor's database cannot say whose chat a conversation is, because it could not be read or holds nothing of the chat yet, the subagent has a row as before. While a subagent is known to be running the database is read again for up to a second and three quarters first, and such a row goes as the subagent ends, where Cursor's hook names the chat it ran as.
- What is read for this is the id of the chat a conversation works for and one flag, from the conversation's own record in Cursor's state database and that of each chat above it, through the same private copy as every other read of that file. Nothing a person wrote is read for it. It was worked out from Cursor 3.23.23's own code; Cursor's hooks reference documents none of it.
- This is for Cursor on this Mac. A Cursor on another machine that reports through the local API is as before, and a subagent left running after its conversation's turn has ended moves that row's clock and nothing else.
