# Notchmeter 0.9.21

### Cursor

- **A subagent's work is on its conversation's row, not on a row of its own.** Cursor runs a subagent as a chat of its own that no window lists, and what that chat sends names it alone, so until now each subagent stood on the Sessions card as a second session beside the conversation that started it, named after its task and counted as one. Notchmeter now reads from Cursor's database which chat a new conversation works for, before that conversation is given a row, and a subagent's commands and thoughts are activity on its conversation's row, under the subagent line that row already had.
- The conversation's row no longer goes quiet while its subagent works. Everything the subagent did was heard on the other row, so 45 seconds into a subagent's run the conversation was shown as one that *may be waiting*, hand and notice included.
- A subagent finishing is not the turn finishing. The extra row gave it a tick, and a *finished* notice where those are on; the conversation's own turn is the only one that does now.
- A command a subagent is held for under *Require notch approval* is answered on its conversation's row.
- The row keeps the conversation's own model while a subagent runs on another. Cursor's two subagent events carry the subagent's model, and the row wore it until the conversation's next event.
- Where Cursor's database cannot say whose chat a conversation is (it could not be read, or holds nothing of the chat a second and three quarters after its first event), the subagent has a row as before, and the row goes when the subagent ends, which is where Cursor's hook names its chat.
- What is read for this is the id of the chat a conversation works for and one flag, from the conversation's own record in Cursor's state database, through the same private copy as every other read of that file. Nothing a person wrote is read for it. It was worked out from Cursor 3.23.23's own code; Cursor's hooks reference documents none of it.
